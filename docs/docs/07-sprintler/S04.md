# S04 — Kullanıcı, üç rol, güvenlik ve kaynak bazlı yetki

**Amaç:** Hasta, personel ve yönetici için kimlik doğrulama ile kaynak-scoped erişimi uygulamak.

**Süre:** 3–4 gün · **Önkoşul:** S03 kurum/şube kimlikleri ve S01 user_account migration. · **İlişkili gereksinimler:** FR-022 FR-023 FR-024 FR-025 FR-026 NFR-001 NFR-002

**Sahiplik:** A security/service; B varsa auth UI/negative tests

## Görevler / uygulama sırası
1. UserAccount, hashli password, Role/Membership ile organization/branch yetki scope tanımla.
2. Spring Security form-login/session/CSRF ve secure default route politikası uygula.
3. Hasta profile owner, staff assignment owner, admin membership scope için AccessPolicy yaz.
4. Controller+service katmanında çapraz tenant ve IDOR negatif testleri ekle.
5. Hatalı login, CSRF olmayan POST, başka hastanın UUID erişimi için test yaz.
6. Seed demo kimlikleri yalnız dev/test profilde konfigürasyon yoluyla yönet.

## Sprint kabul kriterleri / Definition of Done
- [ ] Üç rol login olabilir ve farklı ekran/URL yetkilerine sahiptir.
- [ ] Başka hasta veya şube verisi servisten dahi erişilemez.
- [ ] Plaintext şifre DB'de yoktur; CSRF koruması aktiftir.
- [ ] Bağlı olmayan branch UUID ile role bypass gerçekleşmez.
- [ ] İlgili negatif testler ve görev gerektiriyorsa migration çalıştı (öğrenci bildirdi).
- [ ] Sadece gerekli belgeler güncellendi; geniş kapsamlı refactor yapılmadı.
- [ ] `git diff --check` ve çalışma ağacı kontrol edildi.
- [ ] Öğrenci gerçek gün commit/push gerçekleştirdi (yapıldıysa kanıt verildi).

## Kanıt/çıktı
