# S04 — Kimlik Doğrulama, Spring Security ve Rol Tabanlı Yetki Kapsamı

**Amaç:** Öğretim elemanının zorunlu kıldığı üç kullanıcı rolünü (**Hasta**, **Doktor / Sağlık Personeli**, **Hastane / Klinik Yöneticisi**) Spring Security ile yapılandırmak; parola güvenliğini (BCrypt), oturum yönetimini, CSRF korumasını ve servis seviyesinde çok kiracılı (multi-tenant) yetki denetimini (IDOR engelleme) tamamlamak.

**Süre:** 3–4 gün · **Önkoşul:** Sprint S01 kimlik şeması (`user_account`, `membership`) ve S03 şube kimlikleri hazır olmalıdır.
**İlişkili Gereksinimler:** `FR-022`, `FR-023`, `FR-024`, `FR-025`, `FR-026`, `NFR-001`, `NFR-002` · **İlişkili Testler:** `TC-022` .. `TC-026`, `TC-037`, `TC-038`

---

## 1. Kapsam ve Mimari Sınırlar

### A. Kapsama Alınanlar (In-Scope)
- **3 Temel Kullanıcı Rolü:**
  - `ROLE_PATIENT` (Hasta): Kendi profilini ve randevularını yönetir.
  - `ROLE_STAFF` (Doktor / Sağlık Personeli): Kendi çalışma takvimini ve atandığı randevuları görür/onaylar.
  - `ROLE_ADMIN` (Hastane / Klinik Yöneticisi): Kurum, şube, personel ve hizmet kataloğunu yönetir.
- **Güvenlik Mimarisi (Spring Security 6):**
  - BCrypt parola hashleme mekanizması (plaintext şifre kesinlikle saklanmaz).
  - Form tabanlı giriş (`formLogin`), oturum yönetimi ve `SecurityFilterChain`.
  - CSRF (Cross-Site Request Forgery) koruması (tüm POST/PUT/DELETE isteklerinde zorunlu).
  - Yetkisiz erişimlerde `401 Unauthorized` veya `/login` yönlendirmesi; yetki aşımlarında `403 Forbidden` hata sayfası.
- **Servis Seviyesinde Çok Kiracılı Yetki Kapsamı (`AccessPolicy`):**
  - Yalnızca `@PreAuthorize("hasRole('ADMIN')")` gibi URL/rol bazlı kontrole güvenilmez.
  - Kullanıcının `Membership` kaydı incelenerek; A şubesinin yöneticisinin B şubesinin randevularını onaylaması veya hekimlerini değiştirmesi servis katmanında engellenir (Insecure Direct Object Reference — IDOR koruması).

### B. Kapsam Dışı Bırakılanlar (Strict Out-of-Scope)
- OAuth2, Google/GitHub ile sosyal giriş (akademik MVP dışı).
- JWT (JSON Web Token) veya stateless REST token mimarisi (proje sunucu taraflı MVC monolitidir; session tabanlıdır).
- İki adımlı doğrulama (2FA/MFA) veya SMS OTP entegrasyonu.

## 2. Detaylı İş Paketleri (Work Packages)

### WP-S04-01: Güvenlik Yapılandırması (`SecurityConfig`)
1. `com.example.clinic.common.security.SecurityConfig`:
   - `PasswordEncoder` bean (`BCryptPasswordEncoder(strength = 12)`).
   - `SecurityFilterChain`:
     - Herkese açık rotalar: `/`, `/login`, `/css/**`, `/js/**`, `/actuator/health`.
     - Hasta rotaları: `/patient/**` -> `hasRole('PATIENT')`.
     - Hekim rotaları: `/staff/**` -> `hasRole('STAFF')`.
     - Yönetici rotaları: `/admin/**` -> `hasRole('ADMIN')`.
     - Giriş sayfası: `/login`, Başarılı giriş yönlendirmesi (Role-based redirect).
     - Çıkış işlemi: `/logout` (Oturumu geçersiz kılma, cookie temizleme).
2. `ClinicUserDetailsService`:
   - `UserAccount` ve `Membership` tablolarından `UserDetails` nesnesini oluşturan servis.

### WP-S04-02: Servis Seviyesinde Yetki Politikası (`AccessPolicy`)
1. `com.example.clinic.identity.application.AccessPolicy`:
   - `enforcePatientSelfAccess(UUID patientId, UserAccount currentUser)`: Hastanın yalnızca kendi randevusuna erişebilmesini sağlar.
   - `enforceStaffBranchAccess(UUID branchId, UserAccount currentStaff)`: Personelin yetkili olduğu şubede işlem yapmasını sağlar.
   - `enforceAdminOrganizationAccess(UUID orgId, UserAccount currentAdmin)`: Kurum sınırını aşan istekleri `AccessDeniedException` ile engeller.

## 3. Test Stratejisi ve Doğrulama Matrisi

| Test Metodu | Senaryo | Beklenen Sonuç | Test Türü |
|---|---|---|---|
| `shouldHashPasswordWithBCrypt()` | Yeni hesap oluşturma | DB'de parola BCrypt formatında (`$2a$...`) saklanır | Birim Test |
| `shouldAuthenticateValidUser()` | Doğru e-posta ve şifre ile giriş | Oturum açılır, role uygun dashboard'a yönlendirilir | MVC Slice Test |
| `shouldRejectInvalidPassword()` | Yanlış şifre ile giriş denemesi | Giriş başarısız olur, `/login?error` döner | MVC Slice Test |
| `patientCannotAccessAdminEndpoints()` | Hasta kullanıcısı `/admin/branches` çağırır | `403 Forbidden` yanıtı alınır | Güvenlik Slice Testi |
| `staffCannotApproveOtherBranchAppointment()` | A şubesi hekimi B şubesi randevusunu onaylamaya çalışır | Servis seviyesinde `AccessDeniedException` fırlatılır | Entegrasyon Testi (IDOR) |
| `csrfTokenIsRequiredOnPostRequests()` | CSRF token olmaksızın POST isteği atılır | `403 Forbidden` (CSRF hatası) alınır | Güvenlik Testi |
